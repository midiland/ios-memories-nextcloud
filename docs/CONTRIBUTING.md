# Contributing to Memories iOS

We welcome contributions! Please read this guide before submitting issues or pull requests.

---

## 🌍 Language Policy

### Core Rule
> **All code, comments, documentation, commit messages, and pull request descriptions MUST be in English.**

This is non-negotiable because:
- The project is **public on GitHub**
- English is the **lingua franca** of open-source development
- AI assistants (like Claude, Vibe) **require English** to understand and generate code

### Exception
- **User-facing strings** can be in English + French (see [Localization](#localization))
- **Conversation with users** can be in French (for French-speaking contributors)

## 📝 Localization

Memories iOS supports **English (source) and French** user-facing strings.

### String Catalogs
| File | Purpose | Source Language | Translations |
|------|---------|-----------------|--------------|
| `MemoriesIOS/Resources/Localizable.xcstrings` | App UI strings | English (`en`) | French (`fr`) |
| `MemoriesIOS/Resources/InfoPlist.xcstrings` | Info.plist strings | English (`en`) | French (`fr`) |

### Adding User-Facing Strings

#### SwiftUI Rules
- **✅ DO**: Use **literals** or `LocalizedStringKey`
  ```swift
  Text("Welcome")           // ✅ Literal - will be extracted
  Button("Save")            // ✅ Literal - will be extracted
  Text("Welcome").accessibilityLabel("Welcome screen")  // ✅ Both literals extracted
  ```
- **❌ DON'T**: Use `String` variables or ternary literals
  ```swift
  let message = "Welcome"    // ❌ Not extracted
  Text(message)             // ❌ Not extracted
  Text(isActive ? "On" : "Off")  // ❌ Not extracted
  ```
- **✅ DO**: Use `if/else` with literals
  ```swift
  if isActive {
      Text("On")  // ✅ Extracted
  } else {
      Text("Off") // ✅ Extracted
  }
  ```

#### Non-SwiftUI Rules
For errors, toasts, and other non-UI strings:
```swift
String(localized: "Network error")  // ✅ Extracted
```

### Adding a New Language
1. Add translations to **both** catalogs:
   - `Localizable.xcstrings`
   - `InfoPlist.xcstrings`
2. Use the same **source language** (English) for all strings
3. Add complete translations for the new language

### Interpolation Keys
Use **format specifiers** for interpolated values:

| Type | Specifier | Example |
|------|-----------|---------|
| `Int` | `%lld` | `String(format: "%lld photos", count)` |
| `Int32` / `OSStatus` | `%d` | `String(format: "Error %d", status)` |
| `String` | `%@` | `String(format: "Hello %@", name)` |

**For multiple arguments**: Use **positional specifiers** in translations:
```swift
// English (source): "%lld of %lld files"
// French: "%2$lld sur %1$lld fichiers"
String(format: NSLocalizedString("%lld of %lld files", comment: ""), 5, 10)
```

### Brand Names
Use `verbatim:` for brand names that should not be translated:
```swift
Text(verbatim: "Nextcloud")  // ✅ Never translated
Text(verbatim: "Memories")   // ✅ Never translated
```

### Verifying Localizations
Check for missing translations:
```bash
# Export localizations for verification
xcodebuild -exportLocalizations -project MemoriesIOS/MemoriesIOS.xcodeproj \
  -localizationPath /tmp/l10n -exportLanguage fr -sdk iphonesimulator

# Check the generated fr.xliff for untranslated strings
```

**Caveat**: The static extractor may guess `%@` for interpolated values whose type it cannot infer (e.g., `"\(done) / \(total) files"`). The **runtime key** is what matters (`%lld` for `Int`).

### Testing a Language
```bash
# Launch simulator with French language
xcrun simctl launch "iPhone 16" fr.midiland.memories -AppleLanguages "(fr)"
```

**Note**: The Memories **web UI** language follows the user's Nextcloud settings, not the iOS language.

## 🛠️ Git Guidelines

### Commit Messages
- Write in **English**
- Use **imperative mood** ("Add feature", not "Added feature")
- Follow [Conventional Commits](https://www.conventionalcommits.org/) style:
  ```
  feat: add device photos support
  fix: correct manifest verification
  chore: update project.yml
  docs: add testing guide
  ```

### Co-Authoring
- Include the **AI assistant** as co-author when applicable:
  ```
  Generated by Mistral Vibe.
  Co-Authored-By: Mistral Vibe <vibe@mistral.ai>
  ```
- **Always use this exact format** for AI-generated commits

### Security & Privacy
- **Never include personal information** in code, commits, or documentation:
  - ❌ Personal emails, names, or contact info
  - ❌ API keys, tokens, or passwords
  - ❌ Private URLs or internal paths
  - ❌ Any sensitive data
- **Scan your changes** before committing to ensure no personal data is included

### Branching
- **No direct pushes to `main`**: All changes must go through pull requests
- **Feature branches**: Use descriptive names like `feat/device-photos` or `fix/manifest-verification`
- **Clean history**: Rebase or squash commits before merging

### Pull Requests
- Write **clear descriptions** in English
- Reference **related issues**
- Include **screenshots** for UI changes
- Ensure **all tests pass**
- Add **French translations** for any new user-facing strings

## ⚖️ Code Review

### Before Submitting
1. **Read the code**: Understand the existing patterns and style
2. **Run tests**: Ensure all unit tests pass
3. **Test manually**: Verify your changes work as expected
4. **Check localization**: Add French translations for new strings

### Review Process
- **Small PRs preferred**: Easier to review, faster to merge
- **Address feedback promptly**: Keep the conversation moving
- **Be respectful**: Code reviews are about the code, not the person

---

## 📚 Documentation

### Updating Docs
- Keep documentation **in sync with code**
- Update **all relevant files** when making changes
- Write in **English** (French translations welcome for user-facing docs)

### New Features
For significant new features:
1. Update `README.md` (if user-facing)
2. Update relevant docs in `/docs/`
3. Add tests in `Tests/`
4. Add French translations

## 🚨 Reporting Issues

When reporting issues, please include:
- **iOS version**
- **Device model**
- **Memories version** (from your Nextcloud server)
- **Nextcloud version**
- **Steps to reproduce**
- **Expected vs actual behavior**
- **Screenshots** (if UI-related)
- **Logs** (if available, see [Testing Guide](TESTING.md#logging))
