## 🏗️ Core Architecture (Quick Ref)

The app is a **native Swift/SwiftUI wrapper** around the Memories web interface, with a **NativeX bridge** for native features.

| Component | Role | Details |
|-----------|------|---------|
| **Local Server** | `127.0.0.1:62079` (HTTP/1.1, Network.framework) | Serves verified snapshots + relays to Nextcloud |
| **NativeX Bridge** | `window.nativex` (JS ↔ Swift) | Enables native mode, share sheet, device photos |
| **Offline Mode** | Signed manifest (Ed25519) + snapshot storage | **Never loads JS/CSS from server** |

**Core principle**: The server is **untrusted for code loading**. Web files are only served from verified snapshots.

### 1. Language
- **All code, comments, commits MUST be in English**.

  → [Localization guide in docs/CONTRIBUTING.md#localization](./docs/CONTRIBUTING.md#localization)

- One commit per functional step.

## 📋 Data Flow Summary

### Login
```
URL input → GET /apps/memories/api/describe
  ↓ (version ≥ 9.0.0-rc.1?)
POST /index.php/login/v2 → SFSafariViewController → polling
  ↓
loginName + appPassword → Keychain
```

### Local Mode (Default)
1. **Local server** serves `ShellPage` + verified snapshot (from `/apps/memories/api/describe?manifest=1`)
2. **Relays all other requests** to Nextcloud with Basic auth
3. **Protected** by HttpOnly `local-auth` cookie (per-launch secret) + `Host` check

### NativeX Mode
- Frontend hides Nextcloud header, shows mobile UI
- `http://127.0.0.1/api/…` calls → routed to Swift via `nativexAsync` handler
- Sharing, device photos, toasts via bridge

→ [Full flow in docs/ARCHITECTURE.md#data-flow](./docs/ARCHITECTURE.md#data-flow)

## 🔑 Key Design Decisions

| Decision | Reason | Impact |
|----------|--------|--------|
| iOS 16 minimum | Uses `ObservableObject` (not `@Observable`) | Compatibility |
| Local HTTP server on 127.0.0.1 | Frontend hardcodes `http://127.0.0.1` | Bridge works in secure context |
| No remote loading | Security: server untrusted for code | Snapshot required |
| User-Agent: `MemoriesNative/1.15` | Enables native mode on server | Must stay ≥ 1.1 |
| `playTouchSound` → haptics | iOS native feedback | User experience |
| `downloadFromUrl` → Photos app | Native integration | User convenience |

→ [All decisions in docs/ARCHITECTURE.md#key-design-decisions](./docs/ARCHITECTURE.md#key-design-decisions)

## 💡 For AI: Quick Answers to Common Questions

### Q: How do I add a new SwiftUI view?
A: Add it in `MemoriesIOS/Sources/Views/`. Update `project.yml` if needed, then run `xcodegen generate`.
→ [Development Setup](./docs/DEVELOPMENT.md#project-structure)

### Q: How do I add a user-facing string?
A: Use a **literal** in SwiftUI (`Text("Hello")`). Add English + French to `Localizable.xcstrings`.
→ [Localization Guide](./docs/CONTRIBUTING.md#localization)

### Q: How do I test manifest verification?
A: Use the fake Nextcloud server: `tools/fake-nextcloud/test-scenario.sh dsse`.
→ [Testing Guide](./docs/TESTING.md#fake-nextcloud-server)

### Q: How do I add a new test?
A: Add it in `MemoriesIOS/Tests/` (mirroring `Sources/` structure). Focus on pure logic.
→ [Testing Guide](./docs/TESTING.md#unit-tests)

### Q: What's the User-Agent?
A: `Version/x.y Mobile/15E148 Safari/604.1 MemoriesNative/1.15 MemoriesIOS/<v>`. Keep `MemoriesNative` ≥ 1.1.
→ [Design Decisions](./docs/ARCHITECTURE.md#user-agent--native-mode)

### Q: How does NativeX work?
A: `window.nativex` is defined in `nativex.js`, calls routed to Swift via `WKScriptMessageHandlerWithReply`.
→ [Bridge Details](./docs/ARCHITECTURE.md#nativex-bridge)

## 📌 Remember for AI

1. **Language**: Always use **English** for code, comments, commits.
2. **Offline Mode**: The app **never loads JS/CSS from the server**. Always verify manifests (Ed25519).
3. **Local Server**: All requests to `127.0.0.1:62079` are handled by `LocalHTTPServer`.
4. **NativeX**: `window.nativex` is defined in `nativex.js` (see [bridge spec](./docs/ARCHITECTURE.md#nativex-bridge)).
5. **Device Photos**: Read-only for now. Deduplication via `auid`/`buid` or capture time + aspect ratio.
