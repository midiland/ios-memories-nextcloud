# Memories iOS

Native iOS app (Swift/SwiftUI + WKWebView) for [Memories](https://github.com/pulsejet/memories),
the Nextcloud photo app. Goal: port the official Android wrapper (WebView + "NativeX" bridge).

- Detailed analysis of the Android code and the frontend: `docs/ANALYSIS.md` (read it before touching the NativeX bridge).
- Reference code (not versioned, in `.gitignore`): `reference/memories`.
  Recreate it with `git clone --depth 1 https://github.com/pulsejet/memories reference/memories`.
- Short files, one responsibility per file.

## Language policy

The code is meant to be published on GitHub: **everything written in the repository is in English** —
code, identifiers, comments, doc comments, log messages, documentation (`docs/`, this file, READMEs),
commit messages and PR descriptions.

- Exception: **user-facing UI strings** (SwiftUI texts, `AppError` messages, toasts, accessibility labels,
  Info.plist usage descriptions) are currently in French. Do not translate them in place; the plan is to
  move them to a String Catalog (English source + French translation).
- Conversation with the user can stay in French.

## Commands

```sh
# Regenerate the Xcode project (required after adding/removing files or editing project.yml)
cd MemoriesIOS && xcodegen generate

# Build (the "iPhone 16" simulator was created manually on the iOS 26.5 runtime)
xcodebuild -project MemoriesIOS/MemoriesIOS.xcodeproj -scheme MemoriesIOS \
  -destination 'platform=iOS Simulator,name=iPhone 16' build
```

The `.xcodeproj` is generated but versioned so the app can be built without XcodeGen; `project.yml` is the source of truth.
Info.plist is generated by XcodeGen from the `info:` section of `project.yml` (do not edit it by hand).

## Architecture (`MemoriesIOS/Sources/`)

| Folder | Role |
|---|---|
| `App/` | `MemoriesApp` (@main), `RootView` (login ↔ WebView), `AppConstants`, `Log` |
| `Auth/` | `Credentials`, `CredentialStore` (Keychain), `LoginFlowV2`, `SessionStore` (global state, ObservableObject) |
| `Network/` | `ServerURL` (input normalization → `…/index.php/apps/memories/`), `NextcloudClient` (describe, Login Flow v2, revocation), `AuthenticatedDownloader`, models, `AppError` |
| `Offline/` | `AssetManifest` (describe `?manifest=1`), `ManifestVerifier` (Ed25519 via CryptoKit), `SnapshotStore` (Application Support/offline), `AssetSyncer` (SHA-256, 8 in parallel, reuse), `ShellPage` (local HTML), `CSSPathRewriter`, `OfflineAppLoader` (orchestration) |
| `LocalServer/` | Custom HTTP/1.1 server on Network.framework: `LocalHTTPServer` (127.0.0.1:62079), `HTTPConnection`, `HTTPTypes`, `LocalRouter` (routing modeled on `ServerRouter.kt`), `StaticFiles`, `UpstreamProxy` (streaming relay to Nextcloud) |
| `Web/` | `WebViewModel` (owns the WKWebView), `WebViewFactory` (config), `WebNavigationHandler` (delegates), `WebSessionBootstrapper` (cookies, remote mode), `BackNavigationRule`, `MemoriesWebView` (UIViewRepresentable), `DebugAutomation` (Debug only) |
| `Views/` | `LoginView`, `SafariView`, `WebContainerView` (themed background + toasts), `ErrorView`, `ToastView`, `BackButton`, `DownloadProgressView`, `SharePresenter` |
| `NativeX/` | `NativeXController` (bridge), `NativeXHost` (implemented by `WebViewModel`), `NativeXLoopbackRouter` (`127.0.0.1` routes), `NativeXShareService`, `NativeXMethod`, `WeakScriptMessageProxy` |
| `Resources/` (outside `Sources/`) | `nativex.js`, injected at document start (`__NATIVEX_STATE__` is replaced with the JSON state); `shell-overrides.css` |

### Flow
1. **Login**: URL input → `GET api/describe` (Memories installed? version ≥ 9.0.0-rc.1?) →
   `POST /index.php/login/v2` → login page in `SFSafariViewController` → polling every 3 s for 10 min →
   `loginName` + `appPassword` → Keychain.
2. **Local mode (default)**: the `127.0.0.1:62079` server serves a local page (`ShellPage`) plus the
   JS/CSS of a **snapshot** downloaded from `describe?manifest=1` (JS manifest signed with Ed25519,
   every JS file checked against its SHA-256), and relays everything else to Nextcloud
   (`UpstreamProxy`: Basic auth + `OCS-APIREQUEST`, session cookies in `HTTPCookieStorage.shared`,
   streaming with backpressure, network failure → 504 = "offline" for the frontend).
   - snapshot present → page shown immediately, update checked in the background
     (new snapshot → reload + toast); missing → progress screen, then the page;
   - access protected by the HttpOnly `local-auth` cookie (per-launch secret) + `Host` check;
   - entry page loaded directly at `<webroot>/index.php/apps/memories/` (avoids a frontend redirect);
   - server CSS files use relative paths (`@import '../../dist/icons.css'`): rewritten on the fly
     from their original `href` (`CSSPathRewriter`; the Android app has the same bug).
3. **Remote mode (fallback)** when there is no manifest, the signature is invalid, or the snapshot or
   local server fails: `api/describe` with Basic auth through an ephemeral `URLSession` → Nextcloud
   session cookies copied into `WKHTTPCookieStore` + `nx_auth` cookie (= Basic header, %-encoded, HttpOnly)
   → load `…/index.php/apps/memories/`. In native mode the server turns `nx_auth` into an
   `Authorization` header on every request (`Application::handleNativeHeaders`).
4. **App mode (NativeX)**: `nativex.js` defines `window.nativex` ⇒ the frontend hides the Nextcloud
   header, shows the mobile header and bottom navigation, makes the page transparent and sends its
   color (`setThemeColor`), painted behind the WebView and in the safe areas.
   `http://127.0.0.1/…` calls (fetch and XHR) are diverted in JS to the `nativexAsync` handler
   (`WKScriptMessageHandlerWithReply`): local days/photos are empty; sharing (`/api/share/url`,
   `/api/share/blobs`) really works through the iOS share sheet.
5. **Expired session** (remote mode; redirect to `/login` or 401): automatic re-bootstrap, gives up
   if it loops within 30 s. Authenticated `describe` returning 401 or `uid == null` ⇒ credentials erased, back to login.
6. **Logout**: Settings > Account in the web UI (`nativex.logout`) or the error screen → app password
   revoked (`DELETE /ocs/v2.php/core/apppassword`), Keychain + WebView data + relay cookies +
   local server configuration cleared (snapshots stay on disk).

## Decisions

- **iOS 16 minimum**, Swift 5 language mode, `ObservableObject` (not `@Observable`, which needs iOS 17).
- **Local HTTP server on 127.0.0.1** (like Android) rather than `WKURLSchemeHandler`: the frontend calls
  the bridge on a hard-coded `http://127.0.0.1` (`src/native/api.ts`), `WKURLSchemeHandler` cannot
  intercept http/https, and a loopback origin is a secure context where media playback works.
  The first MVP loaded the remote server directly; it is kept as the fallback mode.
- **User-Agent** suffix: `Version/x.y Mobile/15E148 Safari/604.1 MemoriesNative/1.15 MemoriesIOS/<v>`.
  - `Safari/…` avoids Nextcloud's "unsupported browser" page.
  - `MemoriesNative/<v>` enables native mode on the server (`Util::callerIsNative`); `<v>` must stay
    ≥ `BinExt::NX_VER_MIN` (1.1), otherwise the server shows its "app too old" page. Aligned with Android (1.15).
  - `MemoriesNative` and `window.nativex` go together: never enable one without the other.
- **127.0.0.1 bridge handled in JS**: `fetch`/`XMLHttpRequest` interception, text responses only. It does not
  cover `<img src="http://127.0.0.1/image/…">`; local photo thumbnails would need the local server.
- **Native back button** (`BackNavigationRule`, `BackButton`): in native mode the frontend hides its
  navigation bar outside the main tabs and relies on Android's back button ("On this day", Favorites,
  Videos, Archive, Map, Folders, Search). Floating button at the bottom left, shown when `canGoBack`,
  outside the main tabs (`/`, `/explore`, `/albums`), without a URL fragment (viewer, dialogs) and outside
  pages that have their own back arrow (`/albums/…`, `/places`, `/tags`, `/recognize`, `/facerecognition`).
  The left-edge swipe does the same.
- `playVideo`/`playVideo2`/`destroyVideo` **not exposed**: the frontend keeps its web player.
- `playTouchSound` = haptic feedback; `downloadFromUrl` = download then share sheet
  (credentials are only ever sent to the account's host).
- Status bar: its style follows the system theme, not `isDark` (known limitation when the forced
  Nextcloud theme differs from the iOS theme).
- `SFSafariViewController` rather than `ASWebAuthenticationSession` (Login Flow v2 has no callback scheme).
- Keychain: `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, a single account.
- ATS: `NSAllowsLocalNetworking` only (http for `.local` servers; IP addresses are exempt from ATS).
  No "trust all certificates" option yet (Android option not ported).
- Explore shows a spinner on every visit: the frontend refetches faces/places/tags without caching
  (same on Android and the web). A relay-level stale-while-revalidate cache was offered, not implemented.

## Testing

- **Logs** (Debug): `xcrun simctl spawn booted log stream --level debug --predicate 'subsystem == "gallery.memories.ios"'`
  → one line per local server request (`GET /path → status`) plus offline-mode events.
- **Automated navigation** (Debug): `xcrun simctl launch "iPhone 17 Pro" gallery.memories.ios -MXRoute /thisday -MXBackAfter 5`
  → opens a route through `_m.router.push`, then presses the back button (`DebugAutomation.swift`).
  Do not relaunch the app while the user is using it in the simulator.
- **Local server outside the simulator**: `LocalServer/`, `Offline/{AssetManifest,SnapshotStore,ShellPage,CSSPathRewriter}`,
  `Network/{ServerURL,NextcloudModels}`, `Auth/Credentials`, `App/Log` compile with `swiftc` on macOS
  (harness + fake Nextcloud in Python + `curl`).
- **Signature**: a manifest signed by Node with the default seed of `webpack.manifest-sign-plugin.ts`
  must be accepted in Debug and rejected in Release.
- **Bridge JS**: `nativex.js` can be tested with Node by mocking `window.webkit.messageHandlers`,
  `XMLHttpRequest` and `ProgressEvent`. Live inspection: Safari > Develop > Simulator.
- Simulator with the user's account: **iPhone 17 Pro**. Never delete anything and never log out
  (logging out revokes the app password).

## Next steps

Local photos (PhotoKit) are **on hold**: the user auto-uploads with the official Nextcloud app, whose
renaming/HEIC conversion would break the AUID/BUID deduplication. For reference: PhotoKit
(`/api/days`, `/api/days/{id}`, `/api/image/info`, delete, upload), AUID/BUID identical to the server
(`docs/ANALYSIS.md` §7.3), local server routes for `/image/*` and `/video/*`, real
`configHasMediaPermission`/`getSyncStatus` pushed through `window.__nativexSetState`, `nxsetup` screen
(album selection), `nativex:db:updated` event on photo library changes.

Other candidates: String Catalog for UI strings (English + French), album ZIP extraction to Photos,
self-signed certificate support, app icon and launch screen.
